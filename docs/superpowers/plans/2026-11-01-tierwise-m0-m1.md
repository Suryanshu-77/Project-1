# tierwise M0–M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a tested repo skeleton with CI (M0), plus an OpenAI-compatible `/v1/chat/completions` gateway that forwards an explicitly named model to Anthropic or OpenAI (M1).

**Architecture:** FastAPI app with a startup `lifespan` hook that creates one pooled `httpx.AsyncClient` per provider. Requests are parsed into a normalized Pydantic `ChatRequest`. A provider adapter translates the request to the provider's wire format and the response back into a `ChatResponse`. The route then serializes that as an OpenAI `chat.completion`. There is no routing yet: the model id picks the provider by prefix.

**Tech Stack:** Python 3.12, uv, FastAPI, uvicorn, httpx, Pydantic v2, pydantic-settings, pytest, pytest-asyncio, respx, ruff, mypy, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` (§2, §3.1, §3.2, §6, §7, §8 M0–M1)

## Global Constraints
- Python `>=3.12`, `src/` layout, package name `tierwise`, version `0.1.0`.
- Provider credentials come from env only: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, optional `OPENAI_BASE_URL` (default `https://api.openai.com/v1`). They are never logged or echoed in errors.
- The gateway binds `127.0.0.1:8000` by default.
- One `httpx.AsyncClient` per provider, created in `lifespan` and never per request, with `httpx.Limits(max_keepalive_connections=100, max_connections=250, keepalive_expiry=30)` and `httpx.Timeout(connect=5.0, read=120.0, write=30.0, pool=2.0)`.
- Errors use the OpenAI shape `{"error": {"message", "type", "code"}}`.
- Response headers on success: `X-Tierwise-Model`, `X-Tierwise-Provider`, `X-Tierwise-Reason` (always `override` in M1), `X-Tierwise-Request-Id` (uuid4 hex). `X-Tierwise-Cost-USD` arrives in M2, with the registry.
- **Usage semantics (all adapters):** `input_tokens` is the total prompt tokens, including cached reads and cache writes. `cached_input_tokens` and `cache_write_tokens` are subsets of it.
- Anthropic: `anthropic-version: 2023-06-01`; `max_tokens` defaults to `4096` when the request omits it.
- `stream=true` is rejected in M1 with 400, code `unsupported_parameter` (streaming lands in M2).
- mypy strict on `src/`; ruff with line length 100.

## Review Focus
1. **Tool-call round trip.** An assistant message with `tool_calls` followed by a `tool` role message must become Anthropic `tool_use` / `tool_result` blocks. A tool call reply must come back as OpenAI `tool_calls` with `finish_reason="tool_calls"`. (Task 4)
2. **Multipart content.** `content` given as a list of `{"type":"text"}` / `{"type":"image_url"}` parts, which the OpenAI SDK sends, is translated rather than rejected. Data-URL images become Anthropic base64 sources; `https` URLs become Anthropic URL sources. (Task 4)
3. **System messages anywhere or repeated.** All `system` (and `developer`) messages are joined in order with `"\n\n"` into Anthropic's top-level `system`. Nothing is dropped. (Task 4)
4. **Non-JSON upstream error bodies** (for example an HTML 502 from a proxy) map to a typed error with the body truncated to 500 chars, with no crash and no 500 from the gateway. (Task 3)
5. **Unknown extra request fields** such as `user`, `seed`, `n=1` or `logprobs` are accepted and ignored. Only `top_p` and `stop` are forwarded. Real SDK clients send extra fields, so they must not cause a 422. (Task 2)

### Task 4: Anthropic adapter

**Files:**
- Create: `src/tierwise/providers/anthropic.py`
- Test: `tests/providers/test_anthropic.py`

**Interfaces:**
- Consumes: `send`, `Provider`, and the error types from Task 3; the schema from Task 2.
- Produces:
  - `class AnthropicProvider` with `name = "anthropic"`, `__init__(self, client: httpx.AsyncClient, api_key: str, base_url: str = "https://api.anthropic.com")`
  - `async def chat(...)`, posting to `{base_url}/v1/messages`
  - Pure helpers, unit-tested directly: `to_anthropic(req: ChatRequest, model_id: str) -> dict[str, Any]` and `from_anthropic(data: dict[str, Any]) -> ChatResponse`

Translation rules:
- **Request:**
  - `system` / `developer` messages are joined with `"\n\n"` into the top-level `system` and omitted when there are none.
  - `max_tokens` falls back to `4096`. `temperature`, `top_p` and `stop` (as `stop_sequences`, always a list) are passed through when set.
  - Each `ToolDef` becomes `{"name","description","input_schema": parameters}`.
  - An assistant message's `tool_calls` become `tool_use` blocks, with `input = json.loads(arguments)`. A `tool` message becomes a user message holding a `tool_result` block (`tool_use_id = tool_call_id`).
  - Content parts: text becomes a `text` block. A `data:<mt>;base64,<d>` URL becomes `{"type":"image","source":{"type":"base64","media_type":mt,"data":d}}`; any other URL becomes `{"type":"image","source":{"type":"url","url":...}}`.
  - Headers: `x-api-key`, `anthropic-version: 2023-06-01`.
- **Response:**
  - `text` blocks are concatenated into `content` (`None` if there are none). `tool_use` blocks become `ToolCall` with `arguments = json.dumps(input)`.
  - `stop_reason` mapping: `end_turn` / `stop_sequence` / `pause_turn` → `stop`; `max_tokens` → `length`; `tool_use` → `tool_calls`; `refusal` → `content_filter`.
  - Usage: `input_tokens = input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, `cached_input_tokens = cache_read_input_tokens`, `cache_write_tokens = cache_creation_input_tokens` (missing fields count as 0).

| condition | status | code |

| `RetryableError` | 503 | `upstream_unavailable` |
| `AuthError` | 502 | `upstream_auth_error` (message must not include keys) |
| `FatalError` | upstream status | `invalid_request_error`, upstream message passed through |
