# tierwise M3.5 Implementation Plan: Reasoning Effort

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Choose a reasoning-effort level together with the model, so easy requests stop paying for deep thinking. The plan covers: per-model effort levels in the registry, joint (model, effort) selection, effort-aware affinity, client override, `reasoning_tokens` accounting, and an in-place log schema upgrade.

**Architecture:**
- **Effort options.** A new `options.py` expands each registry model into `Option`s, one per declared effort level.
- **Selector.** It ranks options instead of models: effective quality against the bar, and estimated cost that includes thinking tokens.
- **Affinity.** The table remembers (model, effort) pairs. It treats a different effort as cold only for models whose `effort_in_cache_key` is true.
- **Effort on the wire.** The chosen effort travels on `ChatRequest.reasoning_effort`; each adapter translates it to its provider field.
- **Request log.** It gains two nullable columns, added to existing databases at startup.

**Tech Stack:** as M3. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` §3.5.1 (and §3.5, §3.9, §8 M3.5, §9, §10)

## Global Constraints
- Everything in the M3 plan's Global Constraints still holds.
- **Effort scale:** `EffortLevel = Literal["minimal", "low", "medium", "high", "xhigh", "max"]`, in that order (low to high). `EFFORT_ORDER` is that tuple.
- **Effective quality** is `clamp(model.quality + level.quality, 0, 1)`. The quality bar formula is unchanged.
- **Estimated cost of an option** is `estimated_cost(spec, est_input, est_output, warm_tokens) + thinking_tokens × price_out / 1e6`.
- **Option order:**
  - Options that clear the bar come first, sorted by cost, then by effort order (lower first), then by `-quality`, then by id.
  - The rest follow by `-effective quality`, then effort order, then id.
  - If no option clears the bar, all options are ordered by effective quality, with reason `fallback` (as in M3).
- **"Send nothing":** an option whose effort equals its model's `efforts.default`, or whose model has no `efforts` block, sends no effort field, and its header value is `default`. An option whose effort was set by the client is always sent.
- **Affinity:**
  - Records `(prompt_hash, model_id, effort)`, where effort is `None` for "sent nothing".
  - For `effort_in_cache_key: false` models, any recorded effort of that model counts as warm.
  - For `true` models, only an exact effort match counts. Matching uses the option's *wire effort*: the level sent, or `None` when nothing was sent.
- **Affinity rule:** among the clearing options, find the cheapest one belonging to the incumbent model. If its cost is at most `1.10 ×` the cheapest clearing option's cost, it goes first with reason `affinity`.
- **Client effort** (`ChatRequest.reasoning_effort`, an `EffortLevel | None`; an unknown value gives 400 `invalid_request_error` through validation):
  - For `auto` and `tier`, only options with that exact level are considered. None left gives 422 `no_eligible_model`, whose message names the effort.
  - For a concrete model, it is forwarded unchanged.
- **Wire fields:**
  - Anthropic: `output_config: {"effort": level}`.
  - OpenAI: `reasoning_effort: level` (already part of `model_dump`).
  - Gemini: `generationConfig.thinkingConfig: {"thinkingLevel": level}`.
  - Ollama: nothing is added; the OpenAI pass-through forwards a client value unchanged.
- **Usage:** `Usage.reasoning_tokens: int | None = None` is a subset of `output_tokens`.
  - OpenAI fills it from `completion_tokens_details.reasoning_tokens` (absent → `None`).
  - Gemini fills it from `thoughtsTokenCount` (absent → `None`).
  - Anthropic leaves it `None`.
- **Header:** `X-Tierwise-Effort` is set on every successful response, streamed or not.
- **Log:** `RequestRecord` gains `effort: str | None = None` and `tokens_reasoning: int | None = None`; the logged effort is the header value.
- **Migration:** at `RequestLog.start()`, after `create_all`, add each column of `requests_table` that is missing from the live table with `ALTER TABLE requests ADD COLUMN <name> <type>`. Only nullable columns qualify; anything else is a startup error. Running it again is a no-op.

## Review Focus
1. **Client effort no `auto` candidate supports** (e.g. `reasoning_effort: "minimal"` when only Claude models are configured) gives 422 `no_eligible_model` naming `minimal`, before any upstream call. A valid level the chosen concrete model lacks is forwarded and the provider decides. (Tasks 4, 6)
2. **The default-level option sends no effort field,** so providers keep their own behavior, and the header says `default`. A client-set effort equal to the default *is* sent. (Tasks 2, 6)
3. **Anthropic versus OpenAI cache behavior.** After a turn at `low`, the next turn at `high` is priced cold for an Anthropic-style (`effort_in_cache_key: true`) model and warm for an OpenAI-style one. (Task 4)
4. **An M3-era database** (a `requests` table without the new columns) upgrades at startup: old rows are kept, new rows insert, and a second start changes nothing. (Task 5)
5. **Streamed usage carries `reasoning_tokens`** for OpenAI (its usage chunk) and Gemini (its final usage), so streamed requests log thinking tokens too. (Task 3)

### Task 1: Effort levels in the registry

**Files:**
- Modify: `src/tierwise/schema.py`, `src/tierwise/registry.py`, `config/registry.yaml`
- Test: `tests/test_registry.py`

**Interfaces:**
- Produces:
  - `EffortLevel` and `EFFORT_ORDER` (Global Constraints), defined in `schema.py` so that `ChatRequest` can use them in Task 3 without an import cycle, and re-exported from `registry.py`.
  - `EffortLevelSpec(quality: float, thinking_tokens: int ≥ 0)`, with `extra="forbid"`
  - `Efforts(default: EffortLevel, levels: dict[EffortLevel, EffortLevelSpec])`, where `levels` must be non-empty and contain `default`
  - New fields on `ModelSpec`: `efforts: Efforts | None = None` and `effort_in_cache_key: bool = False`
  - A `ModelSpec` validator that rejects any level whose `quality + shift` falls outside [0, 1]
- In `config/registry.yaml`, every value is marked `# uncalibrated until M5`:
  - **Anthropic** (all three): `effort_in_cache_key: true`, with levels `low`, `medium` and `high`. Defaults: Haiku `medium`, Sonnet `high`, Opus `medium` (spec §10).
  - **Quality shift rule (every model):** the default level gets 0. Each step below the default gets −0.04, cumulative (one step −0.04, two steps −0.08). Each step above the default gets +0.03.
  - **Thinking tokens:** minimal 50, low 150, medium 600, high 2000.
  - **OpenAI `gpt-5.4` and `gpt-5.5`:** levels `minimal`, `low`, `medium`, `high`, with default `medium`. `gpt-4.1-nano` gets no block.
  - **`gemini-3-flash`:** levels `minimal`, `low`, `medium`, `high`, with default `high`.
  - **`gemini-3.1-pro`:** levels `low` and `high`, with default `high`.
  - **Ollama:** no block.
  - A header comment notes that the level lists must be verified against official docs (spec §10).

  - `test_model_without_efforts_is_valid`
  - `test_shipped_registry_efforts`: every Anthropic model has `effort_in_cache_key` true and an `efforts` block, with `default` among its levels; Ollama and `gpt-4.1-nano` have no block.

  - `Option`, a frozen dataclass with fields:
    - `spec: ModelSpec`
    - `effort: EffortLevel | None` (`None` means the model has no effort control)
