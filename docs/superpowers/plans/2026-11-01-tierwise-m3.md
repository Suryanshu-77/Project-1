# tierwise M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the gateway choose the model. Requests for `auto`, `auto:cheap|balanced|quality` or `tier:*` are scored by a rules-based difficulty router, and a selector picks the cheapest capable model that clears the quality bar. The cost estimate is cache-aware, and conversations stick to the model whose prompt cache is still warm.

**Architecture:**
- `router/modes.py` parses the `model` field into a routing target and handles the `[critical]`/`[easy]` tags.
- `router/features.py` and `router/rules.py` turn a request into a difficulty score.
- `router/router.py` runs the pipeline (override, then rules, then fallback) and never raises.
- `affinity.py` remembers which model served which conversation prefix, and when.
- `selector.py` filters the registry, applies the quality bar, ranks the survivors by cache-aware estimated cost, and applies the affinity rule.
- The route serves `candidates[0]`. Failover over the rest of the list is M6.

**Tech Stack:** as M2. No new dependencies: tokens are estimated as characters ÷ 4, and the learned router with its tokenizer is M4.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` (§2 modes, tags and headers; §3.4 router steps 1, 2 and 4; §3.5 selector; §8 M3; §9 M3 hand-off)

## Global Constraints
- Everything in the M2 plan's Global Constraints still holds.
- **Routing values for `model`:**
  - `auto` (also the default when `model` is omitted), `auto:cheap`, `auto:balanced` (same as `auto`), `auto:quality`.
  - `tier:basic`, `tier:moderate`, `tier:flagship`.
  - Anything else is a concrete registry id, served as in M2 (404 `model_not_found` if unknown).
- **Tags:** `[critical]` and `[easy]` are matched case-insensitively, only in the **last user message**, then removed from it along with surrounding whitespace before forwarding. `[critical]` means difficulty 1.0 and `[easy]` means 0.0, both with confidence 1.0 and source `override`. If both appear, `[critical]` wins.
- **Difficulty and confidence** are floats in [0, 1]. Rules confidence is `min(1, 2·|difficulty − 0.5|)`.
- **Quality bar:** `bar = clamp(0.30 + 0.65·difficulty + MODE_SHIFT[mode], 0, 1)`, with `MODE_SHIFT = {"cheap": -0.10, "balanced": 0.0, "quality": +0.10}`. When `confidence < 0.3`, add `BAR_STEP = 0.10` (the upward bias).
- **Router fallback:** any exception inside feature extraction or scoring gives `difficulty=0.7, confidence=0.0, source="fallback"`. The router never raises.
- **Token estimate:** `ceil(len(text) / 4)` over all message text, tool definitions (JSON) and the system prompt. Estimated output is `max_completion_tokens or max_tokens or 512`.
- **Selector filter:** the request's `required_caps ⊆ model.caps`, `est_input + est_output ≤ model.context`, and the model's provider is configured.
  - `required_caps`: `tools` if `req.tools` is set, `vision` if any image part is present, `json` if `response_format` is set.
- **Ranking:**
  - Models with `quality ≥ bar` are sorted by estimated cost ascending, with ties broken by higher quality and then by id.
  - The models below the bar follow, sorted by quality descending. This is the failover tail.
  - If *no* model clears the bar, the order is all filtered models by quality descending, with source `fallback`.
  - An empty filtered set returns 422 `no_eligible_model` (`type: invalid_request_error`), with a message naming the required caps and the estimated tokens.
- **Estimated cost:** `cost(m) = (warm_prefix·price_cache_read' + (est_input − warm_prefix)·price_in + est_output·price_out) / 1e6`.
  - `warm_prefix` is the prefix's estimated tokens when the affinity table shows `m` served this prefix within `m.cache_ttl_s`, and 0 otherwise.
  - `price_cache_read'` falls back to `price_in`.
  - A model with `cache_ttl_s: null` is never warm.
- **Prefix:** the system/developer messages, the tool definitions, and every message before the **last user message**. `prefix_hash` is the SHA-256 hex digest of the canonical JSON (`sort_keys=True`, `separators=(",",":")`) of that list. A request whose only user message is the first message has an empty prefix, and an empty prefix gets no hash and no affinity.
- **Affinity rule:** the incumbent is the model that most recently served this prefix within its TTL. If the incumbent clears the filter and the bar, and `cost(incumbent) ≤ 1.10 · cost(cheapest)`, it goes first with reason `affinity`.
- **Affinity table:** in memory, LRU-bounded to 10,000 prefixes. It records `(model_id, monotonic time)` only after a **successful** response: non-streaming status 200, or a stream that ends with status 200.
- **`tier:X`:** filter (as above) to `tier == X`, sort by estimated cost, reason `override`. An empty result is 422 `no_eligible_model`.
- **Headers:** `X-Tierwise-Reason` is one of `override | rules | affinity | fallback`. `X-Tierwise-Model` is the **chosen registry id**, not the requested `auto…` value.
- **Log fields** filled from M3 on: `mode` (`cheap|balanced|quality`, or `tier:X`, or `null` for a concrete id), `source`, `difficulty`, `confidence` and `prefix_hash`. The record's `model` is the chosen id.
- **`/v1/models`** adds the virtual ids `auto`, `auto:cheap`, `auto:balanced`, `auto:quality`, `tier:basic`, `tier:moderate` and `tier:flagship`, each with `owned_by: "tierwise"`.

## Review Focus
1. **Tag edge cases.** A tag in an earlier message is ignored and left in place. A tag inside a multipart text part is stripped from that part. A message that is *only* the tag becomes 400 `invalid_request_error` ("message is empty after removing the routing tag"), not an empty upstream request. (Task 1)
2. **Requirements nothing can meet.** An image request where no configured model has `vision`, or a prompt larger than every model's context, gives 422 `no_eligible_model` before any upstream call, not an upstream 400. (Tasks 5, 6)
3. **Stale affinity.** An affinity entry for a model that has since left the registry, lost its provider, fails the filter or has outlived its TTL is ignored. No crash, and no affinity reason. (Task 5)
4. **Failed or abandoned requests don't create affinity.** Streams ending 499 or 502, and non-streaming errors, record nothing, so a failing model doesn't become "sticky". (Task 6)
5. **A broken scorer degrades rather than failing.** An exception in feature extraction or scoring gives the fallback decision (difficulty 0.7), and the request is still served and logged with `source="fallback"`. (Tasks 3, 6)
