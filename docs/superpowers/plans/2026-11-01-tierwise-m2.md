# tierwise M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow the M1 gateway to four providers (adding Gemini and Ollama), with streaming responses, a model registry that drives provider resolution and pricing, cached-token-aware cost accounting, and a SQLite request log written off the request path.

**Architecture:**
- A YAML **registry** replaces M1's prefix table: every routable model id maps to a provider, an upstream model name and prices.
- A pure **cost** function prices a `Usage` against a registry entry.
- Each **provider** gains a `stream()` async generator that yields normalized `StreamChunk`s, which are parsed from SSE by one shared helper.
- The **route** serializes those chunks as OpenAI `chat.completion.chunk` events.
- Every request, streamed or not, becomes a `RequestRecord` that is put on a bounded queue. One background writer batches the queue into SQLite.

**Tech Stack:** As M1, plus `pyyaml`, `sqlalchemy[asyncio]>=2` and `aiosqlite`.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` (§2, §3.1–3.3, §3.6 streaming bullet, §3.9, §8 M2)

## Global Constraints
- Everything in the M0–M1 plan's Global Constraints still holds: Python ≥3.12, mypy strict, ruff line length 100, env-only keys that never appear in errors, OpenAI error shape, pooled clients created in `lifespan`.
- **Usage semantics:** `input_tokens` is the total prompt size. `cached_input_tokens` and `cache_write_tokens` are subsets of it. `output_tokens` includes any reasoning or "thinking" tokens the provider bills as output.
- **Shorthand in test descriptions:** `Usage(a, b, ...)` means `Usage(input_tokens=a, output_tokens=b, ...)`, because Pydantic models take keyword arguments only.
- **Prices:** USD per 1M tokens. `price_cache_read: null` means the cached-read price is `price_in`, and `price_cache_write: null` means the cache-write price is `price_in`.
- **Success headers:** `X-Tierwise-Model`, `X-Tierwise-Provider`, `X-Tierwise-Reason` (`override`), `X-Tierwise-Request-Id`, plus `X-Tierwise-Cost-USD` formatted `%.6f` (non-streaming only, because a streaming response's cost isn't known until after its headers are sent).
- **Model resolution:** a model id must exist in the registry, and its provider must be configured. Otherwise the response is 404 `model_not_found`. The M1 prefix table is removed.
- **Stream wire format:** `Content-Type: text/event-stream`. Each event is `data: <json>\n\n` with OpenAI `object: "chat.completion.chunk"`, and the stream ends with `data: [DONE]\n\n`.
- **Store:** `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`. Writes are batched at up to 200 rows or every 250 ms, whichever comes first. The queue is bounded at 10,000; when it is full the record is dropped and `dropped` is incremented. The writer drains the queue on shutdown.
- **New settings (env):** `GEMINI_API_KEY`, `OLLAMA_BASE_URL` (unset means Ollama is disabled; typical value `http://localhost:11434/v1`), `TIERWISE_REGISTRY` (default `config/registry.yaml`), `TIERWISE_DB_URL` (default `sqlite+aiosqlite:///tierwise.db`).
- **Gemini:** base `https://generativelanguage.googleapis.com/v1beta`, header `x-goog-api-key`. Non-streaming calls go to `POST {base}/models/{model}:generateContent`, and streaming calls to `POST {base}/models/{model}:streamGenerateContent?alt=sse`.

## Review Focus
1. **Client disconnects mid-stream.** The upstream HTTP stream must be closed (no leaked connection in the pool), and the request is still logged, with `status=499`. (Task 7)
2. **Streamed tool calls.** Argument fragments arrive across many chunks and must be re-emitted in OpenAI delta form with a stable `index`, `id` and `name` on the first delta for each call. Concatenating the deltas must reproduce valid JSON arguments. (Tasks 3, 4, 5)
3. **Upstream failure after the first chunk was sent.** The client receives a final `data: {"error": {...}}` event and then `[DONE]`, never a truncated connection with no signal. The request is logged with status 502. (Task 7)
4. **Streams with no usage.** Ollama and some OpenAI-compatible hosts may omit usage in the stream. The stream still completes, and the log row has null tokens and cost rather than crashing or reporting $0 as if it were measured. (Tasks 3, 7)
5. **Gemini tool results identified only by `tool_call_id`.** Gemini needs the function *name*, which has to be looked up from the earlier assistant `tool_calls`. An id with no match returns 400, not a 500. (Task 5)

### Task 5: Gemini adapter

**Files:**
- Create: `src/tierwise/providers/gemini.py`
- Test: `tests/providers/test_gemini.py`

**Interfaces:**
- Produces:
  - `class GeminiProvider` with `name = "gemini"`, `__init__(self, client: httpx.AsyncClient, api_key: str, base_url: str = "https://generativelanguage.googleapis.com/v1beta")`, plus `chat` and `stream`.
  - Pure helpers `to_gemini(req: ChatRequest) -> dict[str, Any]`, `from_gemini(data: dict[str, Any], model: str) -> ChatResponse` and `gemini_chunk(data: dict[str, Any], state: _StreamState) -> list[StreamChunk]`.

Translation rules:
- **Request:**
  - `system` and `developer` messages are joined with `"\n\n"` into `systemInstruction: {parts: [{text}]}`.
  - `user` becomes role `user`, and `assistant` becomes role `model`.
  - A text part becomes `{text}`. A `data:` image URL becomes `{inlineData: {mimeType, data}}`. Any other image URL raises `FatalError("gemini", 400, "Gemini accepts only data: image URLs")`.
  - Assistant `tool_calls` become `{functionCall: {name, args: <parsed dict>}}`, reusing the invalid-arguments rule from the Anthropic adapter: arguments that aren't a JSON object give a `FatalError` 400 naming the message.
  - A `tool` message becomes role `user` with `{functionResponse: {name, response: {"content": <text>}}}`, where `name` is looked up from the earlier assistant `tool_calls` by `tool_call_id`. An unknown id raises `FatalError` 400.
- **`generationConfig`:** `temperature`, `topP`, `maxOutputTokens` (from `max_completion_tokens` or `max_tokens`), `stopSequences` (always a list), and `responseMimeType: "application/json"` when `response_format.type` is `json_object` or `json_schema`.
- **Tools:** `tools: [{functionDeclarations: [{name, description?, parameters}]}]`, where `parameters` is omitted when empty. `tool_choice` maps through `toolConfig.functionCallingConfig.mode`: auto → `AUTO`, required → `ANY`, none → `NONE`, and a named function → `ANY` with `allowedFunctionNames: [name]`.
- **Response:**
  - Read `candidates[0].content.parts`. `text` parts are concatenated. `functionCall` parts become `ToolCall` with `id = functionCall.id or f"call_{i}"` and `arguments = json.dumps(args)`.
  - `finishReason` mapping: `STOP` gives `tool_calls` if any function calls are present and `stop` otherwise; `MAX_TOKENS` gives `length`; `SAFETY`, `RECITATION`, `BLOCKLIST`, `PROHIBITED_CONTENT` and `SPII` give `content_filter`; anything else gives `stop`.
  - A response with no candidates (prompt blocked) gives `content=None` and `finish_reason="content_filter"`.
- **Usage (`usageMetadata`):**
  - `input_tokens = promptTokenCount`
  - `cached_input_tokens = cachedContentTokenCount or 0`
  - `output_tokens = candidatesTokenCount + (thoughtsTokenCount or 0)`
- **Stream:** each SSE event is one `GenerateContentResponse`.
  - Each event emits text and tool deltas. Gemini sends complete function calls, so each call becomes one `ToolCallDelta` with id, name and the full arguments.
  - Keep the last `usageMetadata` seen. When an event carries `finishReason`, emit the finish chunk. After the stream ends, emit one usage chunk.

### Task 7: Gateway wiring (four providers, registry, streaming, cost and logging)

**Files:**

**Interfaces:**
- Consumes everything from Tasks 1–6.
- Produces:
  - `Settings` gains `gemini_api_key`, `ollama_base_url`, `registry_path: str = "config/registry.yaml"` (env `TIERWISE_REGISTRY`) and `db_url` (env `TIERWISE_DB_URL`).
  - `create_app(settings, transport, registry: Registry | None = None)`. When `registry` is `None`, the lifespan loads it from `settings.registry_path`.
  - App state set by the lifespan: `app.state.registry`, `app.state.log: RequestLog` (started in the lifespan and stopped on shutdown, after the clients close), `app.state.providers` (adding `gemini` and `ollama`) and `app.state.clients`.
  - The M1 helpers `resolve_provider` and `_PREFIXES` are deleted. In their place, `resolve(model: str, registry, providers) -> tuple[ModelSpec, Provider]` raises `UnknownModel`.
  - `api/streaming.py`: `async def sse_response(chunks: AsyncIterator[StreamChunk], first: StreamChunk, *, request_id: str, model: str, on_done: Callable[[Usage | None, int, str | None], None]) -> StreamingResponse`.

Behavior:
- **Non-streaming:** call `provider.chat(req, spec.wire_id)`. Then:
  - `cost = cost_usd(resp.usage, spec)`
  - `baseline = cost_usd(resp.usage, registry.baseline())`, which is the same tokens priced at the baseline model's rates
  - Add the `X-Tierwise-Cost-USD` header and submit a `RequestRecord` with status 200.
- **Streaming:**
  - Call `provider.stream(...)` and **await the first chunk before returning a response**. An error at that point becomes a normal OpenAI error response with the usual status mapping.
  - The SSE body emits the first chunk plus the rest through `chunk_to_openai`. The final event is `[DONE]`.
  - If a later chunk raises a `ProviderError`, emit `data: {"error": {...}}` with the same mapping as `errors.py`, then `[DONE]`, and log status 502.
  - If the client disconnects (`asyncio.CancelledError` or `GeneratorExit` in the body generator), close the upstream generator (`aclose`) and log status 499.
  - `on_done` receives the last usage seen (or `None`), the final status and an error code, and submits the record. Tokens and cost are `None` when usage is `None`.
