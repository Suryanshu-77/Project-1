# tierwise M6 Implementation Plan: Reliability and Semantic Cache

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A request survives a failing model or provider. The gateway retries, fails over to the selector's next candidate, and stops calling broken models through two-level circuit breakers. A stream that dies before its first content fails over invisibly. Repeated questions are answered from a semantic cache.

**Architecture:**
- **New package `src/tierwise/reliability/`** with three modules:
  - `retry.py`: retries with backoff on the same model.
  - `breaker.py`: circuit breakers per (provider, model) and per provider.
  - `failover.py`: walks the selector's candidates, skipping open circuits.
- **`routes.py`:** both the non-streaming and streaming paths run through `failover.serve`.
- **Streaming:** the first chunk is no longer prefetched blindly. `prime_stream` buffers upstream chunks until real content arrives (or 3 s / 4 KB), so a failure inside that window is still an ordinary, fail-over-able error.
- **`src/tierwise/cache.py`:** an in-memory numpy index that embeds the last user turn with the learned router's MiniLM encoder. The rest of the conversation must match exactly, through a hash in the cache key.

**Tech Stack:** no new dependencies (numpy, the existing ONNX encoder, asyncio).

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` §3.6, §3.7, §4, §7 (fault injection), §8 M6, §9 (M6 hand-off)

## Global Constraints
- Everything in the M3–M5 plans' Global Constraints still holds (ruff 100, strict mypy on `src/`, CI without the train group or `model.onnx`).
- **Retry:** up to **2** retries on `RetryableError`, same model. Exponential backoff with full jitter: `delay = random() * min(2.0, 0.25 * 2**attempt)` seconds. Never retry `FatalError` or `AuthError`.
- **Failover:** after retries, try the next candidate. **Never** fail over on `FatalError`. `AuthError` and connection failures fail over to *other providers* (see Decisions). At most **3** models are tried per request.
- **Breakers:** **5** consecutive failures within **60 s** trip a breaker. It then stays open for **30 s** of cooldown, after which **exactly one** half-open probe is allowed. A success closes the breaker; a failure re-opens it. All four values are configurable.
  - **Model level `(provider, model_id)`:** trips on 429, 5xx and timeouts.
  - **Provider level:** trips on connection failures (refused, DNS, TLS) and `AuthError`. A provider also counts as **open** while **2 or more** of its model breakers are open.
- **Stream hold:** nothing (not even the 200) is sent until the first chunk with non-empty `content` or `tool_calls`, capped at **3.0 s** or **4096 bytes** of buffered chunk JSON. After that point, failures end the stream in-band, as today.
- **Cache:**
  - **Hit:** cosine similarity ≥ **0.95** with an entry younger than **3600 s**. At most **10 000** entries; the oldest are evicted first.
  - **Skipped when:** `temperature > 0.3`, tools are present, the request has `Cache-Control: no-cache`, or the target is a concrete model id (passthrough). (`n` is not modeled: `ChatRequest` ignores it and the gateway always returns one choice.)
  - **On a hit:**
    - The log records `cache_hit=True` and `cost_usd=0`. The baseline cost is computed from the cached usage, so the hit counts toward savings.
    - `X-Tierwise-Reason: cache`, and `X-Tierwise-Model` names the model that originally answered.
- **Log:** `failover_count` is the number of candidates abandoned before the one that served (columns already exist in `RequestRecord`).

## Decisions this plan makes (deviations or gaps in the spec)
- **Unset temperature counts as the provider default, 1.0, so the cache skips it.** The spec skips the cache above 0.3, and most clients never send `temperature`. Caching those requests would replay one sampled answer forever. Cost if wrong: a low hit rate, which can be flipped with a config flag later.
- **`AuthError` fails over to other providers and trips the provider breaker.** It isn't retried, because the request is fine and only our key for that provider is broken. Cost if wrong: one `isinstance` check.
- **Concrete model ids get retries but no failover.** The client asked for that model by name. Cost if wrong: one condition.
- **Breaker health is applied in the failover loop, not inside `select()`.** Skipping open candidates in selector order gives the same result, and the selector stays pure and already tested. Cost if wrong: none for routing. Affinity may still pick an open incumbent, which is then skipped.
- **The semantic match covers the last user turn only.** Everything before it (system prompt, earlier turns), plus the routing target and required caps, is part of an **exact** scope hash. A last user turn longer than 256 tokens is matched exactly (by text hash), never semantically. The encoder truncates at 256 tokens, so two long prompts differing in their tails would otherwise collide. Cost if wrong: fewer hits on long prompts.
- **No cache without the encoder.** The cache reuses the learned router's encoder and thread pool. Without `model.onnx` it is disabled, with the same single warning. Cost if wrong: none (rules-only deployments run uncached).
- **Redis storage and the time-to-first-token "hold" metric are deferred to M7**, with the other metrics and Redis work. Cost if wrong: none in M6.

## Review Focus
1. **A half-open breaker under concurrency:** two requests arrive together after the cooldown, and only one may probe. The other must skip that candidate rather than pile on. Test in Task 2.
2. **Every candidate's circuit is open:** the gateway answers 503 `upstream_unavailable`, naming the circuits, and does not hang or 500. Test in Task 3.
3. **An upstream that sends only empty preamble events for longer than 3 s:** the stream commits and keeps going, with no error and no duplicate chunks. Test in Task 4.
4. **A cache hit for a streaming request:** the client gets a valid SSE stream (content, finish, `[DONE]`) and usage if it asked for it. Test in Task 5.
5. **A client that cancels during the hold window:** the upstream generator is closed, and exactly one log record has status 499. Test in Task 4.

### Task 2: Two-level circuit breakers

**Files:**
- Create: `src/tierwise/reliability/breaker.py`
- Modify: `src/tierwise/config.py`. Add `breaker_failures: int = 5`, `breaker_window_s: float = 60.0` and `breaker_cooldown_s: float = 30.0`.
- Test: `tests/reliability/test_breaker.py`

**Interfaces:**
- Consumes: `RetryableError`, `ConnectionFailure` and `AuthError`.
- Produces:
  - `State = Literal["closed", "open", "half_open"]`
  - `class CircuitBreaker`:
    - `__init__(self, failures: int = 5, window_s: float = 60.0, cooldown_s: float = 30.0, clock: Callable[[], float] = time.monotonic)`
    - `state: State` (read-only property). It moves to `"half_open"` once the cooldown has passed.
    - `try_acquire(self) -> bool`. Closed → True. Open → False. Half-open → True for exactly one caller until that caller records an outcome.
    - `record_success(self) -> None` and `record_failure(self) -> None`
  - `class Breakers`:
    - `__init__(self, **breaker_kwargs)`
    - `model(self, provider: str, model_id: str) -> CircuitBreaker` (created lazily)
    - `provider(self, name: str) -> CircuitBreaker` (created lazily)
    - `available(self, provider: str, model_id: str) -> bool`: non-consuming. False if the provider breaker is open, if 2 or more model breakers of that provider are open, or if this model's breaker is open.
    - `acquire(self, provider: str, model_id: str) -> bool`: consuming. Both levels must grant.
    - `record(self, provider: str, model_id: str, error: ProviderError | None) -> None`
      - `None` counts as success at both levels.
      - `ConnectionFailure` or `AuthError` counts as a provider failure.
      - Any other `RetryableError` counts as a model failure.
      - `FatalError` counts as success: the upstream is healthy and our request was bad.

- Test: `tests/api/test_streaming_route.py` (extend), `tests/api/test_stream_hold.py`

**Interfaces:**
- Produces:
  - `@dataclass class Primed`, with fields `chunks: AsyncGenerator[StreamChunk, None]`, `buffered: list[StreamChunk]` and `pending: asyncio.Task[StreamChunk] | None`. `pending` is the upstream read still in flight when the hold timed out.
  - `async def prime_stream(chunks, hold_s: float = 3.0, hold_bytes: int = 4096) -> Primed`:
    - Reads with `asyncio.ensure_future(anext(chunks))` and `asyncio.wait(timeout=remaining)`. **Never** use `wait_for` on the generator, because cancelling it would close the generator.
    - Returns once a chunk has content or tool calls, the byte cap is reached, the stream ends, or the time runs out.
    - Exceptions raised inside the window propagate, after `aclose()`, so `serve` can fail over.
  - `sse_response(primed: Primed, *, ...)` replaces the `(chunks, first)` parameters. It emits the `buffered` chunks, then awaits `pending` if there is one, then continues.
