# tierwise M4 Implementation Plan: Learned Router

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a trained difficulty classifier (MiniLM embeddings exported to ONNX, plus a small classifier head) to the routing pipeline, between the rules fast-path and the fallback. It should beat the rules router on a held-out test set and add under 10 ms p50.

**Architecture:**
- **Runtime side (`src/tierwise/router/`):**
  - `encoder.py`: token-space truncation, the ONNX session and numpy pooling.
  - `classifier.py`: a numpy forward pass over weights exported from scikit-learn.
  - `learned.py`: a `LearnedRouter` that runs the blocking parts in a small thread pool and maps P(strong needed) to a `RoutingDecision`.
  - `route()` becomes async: override, then rules (returns early when confident), then learned, then fallback.
- **Offline side (`training/`):**
  - Exports the encoder to ONNX.
  - Prepares labels from `routellm/gpt4_dataset`.
  - Embeds prompts **through the runtime encoder**, so training and serving can't drift apart.
  - Trains, picks the threshold on the validation split, and writes artifacts and metrics.
- **Without artifacts:** if the artifacts are missing, the gateway runs rules-only and logs a warning.

**Tech Stack:**
- Runtime: `onnxruntime`, `tokenizers`, `numpy`.
- Offline only, a `train` dependency group: `torch` (CPU), `transformers`, `sentence-transformers`, `scikit-learn`, `huggingface_hub`, `onnx`.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` §3.4 (learned step), §5 (data, train), §7 (encoder tests), §8 M4, §9 (M4 hand-off), §10 (dataset item)

## Global Constraints
- Everything in the M3 and M3.5 plans' Global Constraints still holds (Python ≥ 3.12, ruff line length 100, strict mypy on `src/`, `uv`, pytest with `asyncio_mode = "auto"`).
- **Encoder model:** `sentence-transformers/all-MiniLM-L6-v2` (Apache-2.0), with 384-dim embeddings.
- **Truncation:**
  - At most **256 tokens including special tokens**, done in token space with the `tokenizers` library loading `tokenizer.json`.
  - Segment priority: last user turn, then the previous user turn, then the head of the system prompt.
  - The graph inputs are `input_ids`, `attention_mask` and `token_type_ids`, all `int64`.
- **ONNX:**
  - Dynamic `batch` and `sequence` axes; the output is token embeddings (`last_hidden_state`).
  - Mean pooling over `attention_mask` and L2 normalization happen in numpy.
  - The session is created at startup with `graph_optimization_level=ORT_ENABLE_ALL`, `intra_op_num_threads` from settings (default **2**) and the provider from settings (default **`CPUExecutionProvider`**), then warmed with one dummy run.
- **Blocking work:** `session.run` (and tokenization) never runs on the event loop. It goes through `loop.run_in_executor` on a dedicated `ThreadPoolExecutor(max_workers=2, thread_name_prefix="tierwise-router")`.
- **Fallback decision:** any learned-router error at request time returns `FALLBACK` (difficulty 0.7, confidence 0.0, source `fallback`). The router never fails a request.
- **Rules shortcut:** a rules decision with `confidence >= RULES_SHORTCUT = 0.8` returns immediately, without the learned step.
- **Exit checks:**
  - Learned test ROC-AUC is greater than rules test ROC-AUC on the same held-out split.
  - p50 encoder+classifier latency is below 10 ms on CPU, single request.
- **Artifact directory:** `models/router/`. Committed: `tokenizer.json`, `classifier.npz`, `router.json`, `metrics.json`, `NOTICE`. Ignored by git: `model.onnx` (~90 MB, regenerated by `training/export_onnx.py`).

## Review Focus
1. **A request with no user text** (only images, only tool results, or a whitespace prompt) produces `[CLS][SEP]` and must still yield a learned decision, not an exception. Test in Task 1 and Task 4.
2. **Missing or mismatched artifacts** (no `model.onnx`, classifier input dimension ≠ 384, a corrupt `router.json`) mean startup logs a warning and runs rules-only, with no crash. Tests in Task 3 and Task 5.
3. **Huge CJK or emoji input** (50k characters) is never more than 256 tokens, and `[CLS]`/`[SEP]` are intact. Test in Task 1.
4. **Concurrent requests** never block the event loop while inference runs, and 20 concurrent decisions all complete. Test in Task 4.
5. **Train/serve skew:** training embeds with the same `build_inputs` + `OnnxEncoder` path the gateway uses, and the parity test compares that path with `sentence-transformers`. Task 2 (parity) and Task 6 (embedding goes through `tierwise.router.encoder`).

## Decisions this plan makes (deviations from the spec text)
- **Classifier artifact is `classifier.npz` + `router.json`, not `router_model.joblib`.**
  - Unpickling joblib needs scikit-learn at runtime and runs arbitrary code from a file.
  - The weights of a logistic regression or a small MLP fit in an `.npz` and run in about 10 lines of numpy.
  - Cost if wrong: one loader function.
- **Learned-router errors at request time use `FALLBACK`, as the spec says, even though a rules decision exists.** Cost if wrong: one changed line in `route()`.
