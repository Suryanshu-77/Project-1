# tierwise 0.9.1 Hardening Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fix the deferred review findings a real user could hit, and release 0.9.1.

**Architecture:** no new components. Each fix lives in the module that owns the behavior:
- `selector.py`: the capability and context check, shared with the flywheel.
- `routes.py`: the sampling hook.
- `config.py`: the cache directory.
- `training/retrain.py`: version folders and the encoder check.
- `fetch.py`, `flywheel.py`: the download size cap and the judge's score.

**Tech Stack:** existing only.

**Spec:** `docs/superpowers/specs/2026-11-01-tierwise-design.md` §5.3

## Global Constraints
- Everything in the M3–M9b plans' Global Constraints still holds.
- **Encoder size, pinned:** 90,405,214 bytes (`MODEL_SIZE`), next to `MODEL_SHA256`.
- **The contrast rule is the spec's:**
  - another model answered → `baseline_model`
  - the baseline answered → the cheapest `basic` model by `price_in + price_out`, ties broken by id

  Either way, the contrast model must pass the selector's `fits` check for the stored request.

## Review Focus
1. **A vision or tool request routed to the flagship** must not pick a basic contrast model that lacks the capability. With none that fits, the sample fails with no paid call. Test in Task 1.
2. **A sampled stream with no usage chunk** is sampled, but not cached. Test in Task 2.
3. **`Path.home()` raising `RuntimeError`** must not stop `import tierwise.config`. Test in Task 3.
4. **A retrain that crashes after creating its version folder** leaves no folder named like a version. Test in Task 4.
5. **A download larger than the pinned size** stops before the file is complete, and leaves nothing behind. Test in Task 5.
